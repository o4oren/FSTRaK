# FSTRaK EFB App — Design Spec

**Date:** 2026-04-09  
**Branch:** feat/openfightmaps-support (additive work; own commit)  
**Status:** Approved for implementation

---

## 1. Goal

Make the FSTRaK moving map available as an **MSFS 2024 EFB app** (tablet app) in addition to the existing toolbar panel, so users who prefer the EFB tablet can install that instead of (or alongside) the toolbar panel. Both addons ship in the same release zip and are independent MSFS Community packages.

---

## 2. Background

### Existing toolbar panel

`msfs-addon/fstrak-ingame-panel/` is an MSFS Community addon registered via `InGamePanels/fstrak-ingame-panel.xml`. Its `CustomPanel.html` renders an `<iframe>` pointing to `http://127.0.0.1:8765/panel` — the Leaflet moving map served by FSTRaK's tile server. No build step required.

### EFB app mechanics (MSFS 2024)

EFB apps live at `html_ui/efb_ui/efb_apps/<AppName>/` inside an addon package. The entry point is a **compiled JavaScript bundle** (TypeScript/JSX built with esbuild) that calls `Efb.use(MyApp)` to self-register with the EFB container. The app class declares a `name`, an `icon`, and renders a single `AppView` — which can contain any JSX, including a full-screen `<iframe>`.

The build toolchain depends on:
- `@efb/efb-api` — from the MSFS 2024 SDK, referenced as a local file dependency
- `@microsoft/msfs-sdk` — npm tarball (vendored or downloaded)
- `esbuild`, `typescript`, SASS plugin — standard devDependencies

---

## 3. Approach

**Two separate MSFS Community packages inside `msfs-addon/`:**

```
msfs-addon/
├── fstrak-ingame-panel/     (existing, unchanged)
└── fstrak-efb-app/          (new)
```

Both folders are included in the release zip. Users copy whichever they want (or both) into their Community folder.

## 4. Package Structure

```
msfs-addon/fstrak-efb-app/
├── manifest.json
├── layout.json                      (generated by generate_layout.py)
├── package.xml
├── generate_layout.py               (copied from fstrak-ingame-panel)
├── .gitignore                       (ignores efb_api/, dist/, node_modules/)
├── PackageDefinitions/
│   └── fstrak-efb-app.xml
└── PackageSources/
    ├── efb_api/                     (from MSFS SDK — gitignored, see §6)
    ├── html_ui/
    │   └── Icons/
    │       └── ICON_FSTRAK_EFB_APP.svg   (copy of toolbar SVG icon)
    └── FSTRaKApp/
        ├── package.json
        ├── tsconfig.json
        ├── build.js
        ├── .env
        ├── src/
        │   ├── FSTRaKApp.tsx
        │   └── FSTRaKApp.scss
        └── dist/                    (gitignored, build output)
```

### Output path

The build produces files under `html_ui/efb_ui/efb_apps/FSTRaKApp/` — this is the COUI path the EFB runtime scans to discover apps.

## 5. The TSX App (`FSTRaKApp.tsx`)

```tsx
import { App, AppBootMode, AppSuspendMode, AppView, AppViewProps,
         Efb, RequiredProps, TVNode } from '@efb/efb-api';

class FSTRaKAppView extends AppView<RequiredProps> {
  public render(): TVNode {
    return (
      <div style="width:100%;height:100%">
        <iframe
          src="http://127.0.0.1:8765/panel"
          style="width:100%;height:100%;border:none"
        />
      </div>
    );
  }
}

class FSTRaKApp extends App {
  public get name(): string { return 'FSTRaK'; }
  public get icon(): string { return 'coui://html_ui/Icons/ICON_FSTRAK_EFB_APP.svg'; }

  public override get bootMode(): AppBootMode { return AppBootMode.COLD; }
  public override get suspendMode(): AppSuspendMode { return AppSuspendMode.SLEEP; }

  public async install(): Promise<void> {
    await Efb.loadCss('coui://html_ui/efb_ui/efb_apps/FSTRaKApp/FSTRaKApp.css');
  }

  public render(props: AppViewProps): TVNode {
    return <FSTRaKAppView {...props} />;
  }
}

Efb.use(FSTRaKApp);
```

### `FSTRaKApp.scss`

Minimal: sets the view to `width: 100%; height: 100%; overflow: hidden` so the iframe fills the EFB panel.

## 6. `efb_api/` — SDK dependency

`PackageSources/efb_api/` must be sourced from the MSFS 2024 SDK (installed via Developer Mode → SDK Installer). It is **not committed to git**.

**.gitignore entries for `fstrak-efb-app/`:**
```
PackageSources/efb_api/
PackageSources/FSTRaKApp/dist/
PackageSources/FSTRaKApp/node_modules/
```

The SDK path on a typical Windows dev machine is:
`C:\MSFS SDK\EFB\TemplateApp\` — copy the `efb_api/` subfolder from there.

## 7. `package.json` for `FSTRaKApp/`

Key fields (based on the Asobo template):

```json
{
  "name": "@efb/fstrakapp",
  "dependencies": {
    "@efb/efb-api": "file:../efb_api/dist/",
    "@microsoft/msfs-sdk": "file:../vendor/microsoft-msfs-sdk-2.0.5.tgz"
  },
  "devDependencies": {
    "esbuild": "^0.21.3",
    "esbuild-sass-plugin": "^3.3.0",
    "typescript": "~5.6.2",
    "cross-env": "^7.0.3"
  },
  "scripts": {
    "build": "node ./build.js",
    "watch": "cross-env SERVING_MODE=WATCH node ./build.js"
  }
}
```

The `microsoft-msfs-sdk` tarball is vendored at `PackageSources/vendor/` (committed — it's a redistributable from Asobo) or downloaded via the SDK.

## 11. Open questions / risks

| Item | Note |
|------|------|
| `@microsoft/msfs-sdk` tarball | Needs to be sourced from SDK. Either vendor it in the repo or document the path. Confirm redistributability. |
| `content_type` in manifest.json | Asobo sample uses `""`. May need a specific value for EFB packages — verify against a working community EFB app. |
| EFB iframe HTTP policy | MSFS Coherent GT allows `http://127.0.0.1` in iframes (confirmed working in toolbar panel). Should carry over to EFB. |
| MSFS 2020 behaviour | EFB package will simply not appear; no harm. |
